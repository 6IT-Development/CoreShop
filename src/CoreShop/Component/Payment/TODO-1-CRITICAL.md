## Data written wrongly

### C-01 — (reproduced) The translated setters of `PaymentProvider` and `PaymentProviderRule` write into the **fallback** locale's translation; values for other languages overwrite the default language and the other translations are never created
- **Where:** `Model/PaymentProvider.php:98-101` (`setTitle()`), `:108-111` (`setDescription()`), `:118-121` (`setInstructions()`), `:143-149` (`getTranslation()` with `$useFallbackTranslation = true` by default), `Model/PaymentProviderRule.php:59-62` (`setLabel()`), `:64-70`. Root behaviour: `Component/Resource/Model/TranslatableTrait.php` `getTranslation()` (returns the fallback translation when the requested locale does not exist yet). Fallback locale: `Component/Resource/Factory/TranslatableFactory.php:42` (default locale on `createNew()`), `Component/Core/Translation/TranslatableEntityPimcoreLocaleAssigner.php` (default locale on load). **(dependent)** callers: `CoreBundle/Fixtures/Data/Demo/PaymentProviderFixture.php:70-74`, `Behat/Context/Setup/PaymentContext.php:100-102`, and every project import / migration script that sets per-language values.
- **Problem:**
  - `setTitle($title, 'de')` calls `getTranslation('de')`. When no `de` translation exists yet but the fallback (default) locale `en` does, the trait **returns the `en` translation**, and the setter overwrites the English title with the German one. No `de` translation is created.
  - Reproduced with the vendored classes: `setTitle('Invoice', 'en'); setTitle('Rechnung', 'de');` → `getTitle('en') === 'Rechnung'`, `count(getTranslations()) === 1`. Same for `PaymentProviderRule::setLabel('Fee', 'en'); setLabel('Gebühr', 'de');` → English label is `Gebühr`.
  - The demo fixture loops over all valid languages, so a demo install stores only the default-language row, filled with the **last** language's description and instructions (random faker text, so it is not visible; with real texts, the storefront in the default language shows the last language's text). Import scripts that set the title per language silently lose all non-default languages and corrupt the default one.
  - Every other translatable model in CoreShop passes `false` for exactly this reason: `Component/Taxation/Model/TaxRate.php:71`, `Component/Address/Model/{Country.php:104,State.php:88}`, `Component/Product/Model/ProductUnit.php:76-106`. The payment models do not. `Component/Shipping/Model/Carrier.php:104,114` has the same bug (no Shipping TODO exists yet; fix it together).
  - The admin is not affected: the translation form writes into the `translations` collection by locale (`ResourceTranslationsType`), not through these setters.
- **Fix:**
  - Setters: `$this->getTranslation($language, false)->setTitle($title);` (and the same for `setDescription()`, `setInstructions()`, `setLabel()`).
  - Getters may keep the fallback.
  - Data repair: for shops installed with the demo fixture or imported by script, check `coreshop_payment_provider_translation` / `coreshop_payment_provider_rule_translation` for missing locales and re-import the texts.
  - Add a unit test with two locales for each setter (TODO-3 **I-12**).
