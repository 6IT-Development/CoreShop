## Security

### C-01 — `RulesProcessor` serializes every parameter verbatim into the Messenger transport; the raw password-reset token is stored in plain text in the database, which defeats the hashed-token hardening
- **Where:** `Processor/RulesProcessor.php:32-55` (only `order` / `store` are reduced to ids, everything else goes into `NotificationMessage::$params` unchanged), `Messenger/NotificationMessage.php:23-29`. Transport: `NotificationBundle/Resources/config/pimcore/messenger.yml:4-15` (`doctrine://default?queue_name=coreshop_notification`, failure transport `coreshop_notification_failed`, PHP serializer). **(dependent)** `CoreBundle/EventListener/NotificationRules/CustomerListener.php:47` (`'resetLink' => $event->getResetLink()`), `:101-110` (`confirmLink` + `token` for the newsletter double opt-in), `FrontendBundle/Controller/RegisterController.php:93-107` (raw token in the link, only `hash('sha256', $rawToken)` is stored on the user), `UserBundle/Pimcore/Repository/UserRepository.php:43` (TTL 3600 s), `MessengerBundle/Messenger/MessageRepository.php:54` (`print_r()` of the pending message in the admin).
- **Problem:**
  - The password-reset flow was hardened on purpose (comments reference CWE-640 / CWE-613): only the SHA-256 hash of the token is persisted, so a database read does not give access to customer accounts.
  - The notification for the same event puts the **raw** reset link into the message params. `RulesProcessor` dispatches it to the Doctrine transport, which writes `serialize($envelope)` into `messenger_messages.body`. Until the worker has handled the message, the plaintext token sits in the same database the hash was meant to protect.
  - The window is not just "a few seconds": if no worker runs (a common misconfiguration), or the mail fails and Messenger retries with back-off (5 min … 80 min, `messenger.yml:7-10`), the row stays for longer than the 1 h TTL. After the last retry the message is moved to `coreshop_notification_failed` and stays there **forever**, so every DB dump / backup taken in that window contains working reset links.
  - Every admin user with `coreshop_permission_messenger` can open **Messenger → Pending / Failed messages → Details** and read the link (`print_r()` of the whole message, `MessageRepository.php:54`), i.e. take over any customer account that requested a reset, without any customer-related permission.
  - Same class of leak, lower impact: the newsletter double-opt-in `token` / `confirmLink` (`CustomerListener.php:109-110`; that token is stored in plain text on the customer anyway), and any secret a project passes in params (one-time login links, voucher codes, …). The component offers no way to mark a parameter as sensitive.
- **(plausible):** the data path is all in the code (listener → `RulesProcessor::applyRules()` → `MessageBusInterface::dispatch()` → Doctrine transport → `messenger_messages`); the content of the table was not inspected on a running shop.
- **Fix:**
  - Do not put secrets into the message. For the password reset, pass only the user id and create the token **in the worker** (move the token generation from the controller into the mail action / a dedicated action, or dispatch the reset mail synchronously and keep only a "mail sent" notification asynchronous).
  - Short term, in this component: add an explicit contract for sensitive params, e.g. `RulesProcessorInterface::applyRules(…, array $params = [], array $sensitiveParams = [])`, or a `SensitiveParameter` value object that is encrypted (e.g. `sodium_crypto_secretbox()` with a key derived from `kernel.secret`) before dispatch and decrypted in `NotificationMessageHandler`. Do not rely on `#[\SensitiveParameter]`: it only hides values from stack traces, not from serialization.
  - Configure `failure_transport` retention / a cleanup command for `coreshop_notification_failed`, so failed messages with personal data (names, e-mails, see MessengerBundle C-01) do not stay forever (GDPR).
  - Add a test that the serialized `NotificationMessage` for `coreshop.user.request_password_reset` does not contain the raw token.
